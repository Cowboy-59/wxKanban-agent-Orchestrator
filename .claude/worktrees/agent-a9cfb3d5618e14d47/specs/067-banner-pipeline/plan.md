# Implementation Plan: Banner Studio — Pipeline & Data Foundation

**Spec**: 067 — [spec.md](spec.md) | **Tasks**: [tasks.md](tasks.md)
**Scope**: [`specs/Project-Scope/070-banner-studio.md`](../Project-Scope/070-banner-studio.md)
**Stack**: Express + React/Vite + PostgreSQL/Drizzle + Tailwind/shadcn (per `stack.md`); S3/CloudFront for binaries; Puppeteer for HTML→image.

---

## Approach

Reuse, don't reinvent. The render path is the existing Puppeteer flow with `.pdf()` swapped for `.screenshot()`; storage is the existing marketing S3/CloudFront lib with one direct-put helper added; the image provider mirrors the SCOPE-065 `llm-provider.ts` abstraction (but returns bytes, not text). The only net-new surface area is three tables, `image-provider.ts`, `BannerRenderService.ts`, and one admin router. Build bottom-up: **schema → provider → render → storage → routes**, so each task has its dependency already in place.

## Data model — three new tables (one migration)

New schema files under `src/db/schema/`, all exported from `src/db/schema/index.ts`. Conventions: plural lowercase tables, lowercase no-underscore columns, UUID v7 PKs (`$defaultFn(() => uuidv7())`), `companyid` cascade FKs — verified against `marketingassets.ts`/`campaignposts.ts`.

- **`marketinglinks`** — first-class tracked link (foundation for SPEC-068): `id`, `companyid` (FK cascade), `campaignid` (FK set-null), `code` (unique, opaque, non-enumerable), `destinationurl`, `utmsource`/`utmmedium`/`utmcampaign`, `clickcount` (int default 0), `assetid` (nullable), `status` (`active|archived`), `createdbyid`, `createdat`/`updatedat`. Index: unique(`code`), `companyid`, `campaignid`, `status`.
- **`marketingbanners`** — `id`, `companyid` (FK cascade), `campaignid` (FK set-null), `linkid` (FK→marketinglinks), `title`, `sizepreset`, `width`/`height` (frozen), `layout`, `prompt`, `headline`, `subhead`, `ctatext`, `brandtokens` (jsonb), `backgroundurl`, `renderedurl`, `frames` (jsonb, `[]`), `status` (`draft|published|archived`), `targetsegment` (nullable), `slot` (nullable), `createdbyid`, `createdat`/`updatedat`. Index: `campaignid`, `status`, (`targetsegment`,`slot`).
- **`marketinglinkclicks`** — created here (populated in SPEC-068): `id`, `linkid` (FK cascade), `clickedat`, `iphash`, `uaclass`, `referrer` (nullable), `counted` (bool). Index: `linkid`, `clickedat`.

Migration generated via `npm run db:generate`, applied via the project's direct-pg pattern (`pg.Client` + transaction — drizzle-kit push needs a TTY; kit `dbpush` is broken). The app prod DB == local `.env` DB, so the local apply also migrates app-prod (`?sslmode=require` required).

## Image provider — `src/server/ai/image-provider.ts` (new)

A deliberate sibling of `src/server/ai/llm-provider.ts`, image-only, returns bytes: `getImageProvider()` reads `IMAGE_PROVIDER` (default `gemini-imagen`); `generateImage(prompt, {width,height})` returns `{ bytes: Buffer } | null` (fail-open, never throws). Gemini Imagen via the Google Generative Language endpoint family already used for Gemini text in `llm-provider.ts`, reusing `GEMINI_API_KEY`; base64 response → `Buffer`. The `openai-gpt-image` branch is left as a future env-flip stub (throws "not implemented" / returns null), **not** built. A `BRAND_PROMPT_SUFFIX` constant ("muted navy + warm amber palette, professional, no text, leave negative space top-left for overlay") is appended to every prompt. Soft-throttle via the existing SCOPE-065 helper.

## Render service — `src/server/services/BannerRenderService.ts` (new)

Patterned on `MarkdownPdfRenderer.ts`: `puppeteer.launch({headless,args:['--no-sandbox','--disable-setuid-sandbox']})`, `page.setViewport({width,height,deviceScaleFactor:2})`, `page.setContent(buildBannerHtml(opts), {waitUntil:'networkidle0'})`, wait on `document.fonts.ready` + `await img.decode()` for the logo, then `page.screenshot({type:'png', clip:{x:0,y:0,width,height}})`, `try/finally browser.close()`. `buildBannerHtml(opts)` renders the AI image as `background-image:cover` on a preset-sized box with the overlay (headline/sub/logo/CTA) on top, laid out by the `layout` archetype. Brand tokens live in `src/server/lib/banner-brand.ts` (new) — navy `#0f1722`, amber `#c8761b`, system font stack, logo CloudFront URL — extracted from `marketing/site/index.html`; per-banner `brandtokens` overrides merge over these. A `BANNER_PRESETS` constant map (`og` 1200×630, `mrec` 300×250, `leaderboard` 728×90, `skyscraper` 160×600, `halfpage` 300×600, `mobile` 320×50) → `{width,height,layout}` is the single source of truth for dimensions + archetype.

## Storage — extend `src/server/lib/marketing-assets-s3.ts`

Add `putBannerObject({ key, body, contentType })` — a direct server-side `PutObjectCommand` (the file already imports the S3 client + `PutObjectCommand`; today it only presigns). The server holds the rendered/generated bytes, so a direct put avoids the client round-trip. Reuse `publicUrlForKey()` + existing `MARKETING_ASSETS_BUCKET/REGION/BASEURL` + the `public/` prefix + already-allowed `image/png`. Keys: `public/banners/<id>/bg.png` and `public/banners/<id>/render-<v>.png` (versioned — `<v>` is a short render counter/hash so the URL changes each render).

## Routes — `src/server/routes/marketingBanners.ts` (new)

Mounted in `src/server/app.ts` at `/api/sysadmin/marketing/banners` **before** the broad `marketingAdminRoutes` mount (same ordering discipline as `marketingAi`/`newsletter`), behind `authenticateToken` + `requireSysAdmin`, Zod-validated, structured like `marketingAdmin.ts`. Endpoints this spec: `GET /banners` (filters), `POST /banners` (create draft + create/link a `marketinglinks` row, freeze width/height/layout from the preset map, validate destination host via the shared allowlist helper), `GET /banners/:id`, `PATCH /banners/:id`, `DELETE /banners/:id`, `POST /banners/:id/generate-bg` (throttled → `generateImage` → `putBannerObject` bg → set `backgroundurl`; fail-open), `POST /banners/:id/render` (→ `BannerRenderService` → `putBannerObject` versioned render → set `renderedurl`). DB via `src/db/client.ts`. The `/banners/:id/export` endpoint + `/links` CRUD are SPEC-068/069.

## Conventions

Routes via `index.ts → app.ts`; DB via `src/db/client.ts`; 100% TypeScript (no `any`/`@ts-ignore`); Pino-only; fences written by the orchestrator at `implement`; nothing pushed until the user says push.

## Risks

- **Headless fonts/logo** — use the system font stack already in the container; `document.fonts.ready` + `img.decode()` before screenshot; verify in the deployed image, not just locally.
- **AI cost/latency/safety** — throttle generate; keep generate/render separate; a content-filter refusal is fail-open `null`, not a 500.
- **Stale cache** — versioned render keys so the URL changes each render (no CloudFront invalidation).
- **Brand drift** — the `BRAND_PROMPT_SUFFIX` + the overlay (logo/colours/copy) as the consistent brand layer; human review before publish (publish is SPEC-069).
- **Wrong DB / TLS** — apply migration via direct-pg against the `?sslmode=require` URL; remember local `.env` DB == app prod DB.
