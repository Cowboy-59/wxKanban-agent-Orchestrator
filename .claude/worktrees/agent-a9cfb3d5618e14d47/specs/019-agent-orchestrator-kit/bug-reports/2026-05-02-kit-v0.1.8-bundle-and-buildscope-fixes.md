## BUG-1 (blocker) — Distributed `node_modules` are Linux-only

**Where the bug lived**: orchestrator release workflow ([`.github/workflows/release.yml`](https://github.com/Cowboy-59/wxKanban-agent-Orchestrator/blob/main/.github/workflows/release.yml)).

**Cause**: The release runner (Ubuntu) ran `npm install` for the root, `wxkanban-agent/`, and `mcp-server/`, then copied the entire tree — including every `node_modules/` — into staging before tar/zip. `@esbuild/linux-x64`, `bcrypt` Linux binaries, etc. shipped in the kit; Windows/Mac consumers crashed on first invocation.

**Fix**: Strip `node_modules` from the kit staging directory after build steps complete. `find staging -type d -name 'node_modules' -prune -exec rm -rf {} +` runs after the cp. `scripts/init.mjs` already self-bootstraps deps on the consumer machine for the right platform, so removing the bundled binaries has no consumer-visible cost.

## BUG-2 (blocker) — `bin/wxkanban-agent.cmd` syntax-errors on Node ≥ 20

**Where the bug lived**: orchestrator [`bin/wxkanban-agent.cmd:16`](https://github.com/Cowboy-59/wxKanban-agent-Orchestrator/blob/main/bin/wxkanban-agent.cmd#L16).

**Cause**: The Windows wrapper used cmd caret-escapes (`^'`) inside a `node -p` argument to extract the major version. Modern Node + cmd combinations do not strip the carets; Node sees them as literal characters and the JS parser fails. `%NODE_MAJOR%` ends up empty and the `LSS` comparison crashes with `20 was unexpected at this time.`

**Fix**: Replace the fragile `node -p` invocation with `for /f "tokens=1 delims=v." %%V in ('node --version') do set "NODE_MAJOR=%%V"` — splits `v20.10.0` into tokens by both `v` and `.`, picks the first non-empty token (the major). No quoting hazards.

## BUG-3 (blocker) — `wxkanban-agent` postinstall hook crashes consumer projects

**Where the bug lived**: orchestrator [`wxkanban-agent/package.json`](https://github.com/Cowboy-59/wxKanban-agent-Orchestrator/blob/main/wxkanban-agent/package.json) `postinstall` + [`scripts/copy-repo-rules-to-project.js`](https://github.com/Cowboy-59/wxKanban-agent-Orchestrator/blob/main/scripts/copy-repo-rules-to-project.js).

**Cause**: The `postinstall` hook ran `node ../scripts/copy-repo-rules-to-project.js` on every `npm install` inside `wxkanban-agent/`. The script imported `fs-extra` (not in `wxkanban-agent/package.json` deps) and resolved `../../../memories/repo` — a path that only exists in the kit-author tree. Combined with BUG-1, consumers had to pass `--ignore-scripts` just to recover from the platform mismatch.

**Fix**: Removed `postinstall` and `postupdate` hooks from `wxkanban-agent/package.json` (orchestrator + this repo). The kit already ships `_wxAI/rules/` populated from the orchestrator repo at release time — the runtime copy was redundant. The script itself was hardened with an early-return when `REPO_MEMORY_DIR` is absent so any explicit invocation no longer crashes.

## BUG-5 (high — data integrity) — `buildScope` invents schema/API/component content that contradicts the user's `scopeBoundary` / `outOfScope`

**Where the bug lived**: this repo, [`mcp-server/src/utils/project-kit.ts → buildScopeContent`](../../../mcp-server/src/utils/project-kit.ts).

**Cause**: Four sections of every generated scope (`Data Requirements`, `API Routes`, `Frontend Components`, `Key Entities`) were built from feature-name string interpolation regardless of input. The function had no input fields for these sections, so they were *always* templated. A `featureDescription` like "UAT foundation init database connections" produced invented `companyuats`, `uatevents`, `uathistory` tables, six invented API routes under `/api/foundation-init-database-connections-uat`, four invented React components, and four invented entity types — even when `scopeBoundary` explicitly said "no new tables, only take-over of 7 existing tables."

**Impact**: every `buildscope` output contained directly contradictory statements. `create_specs` and human reviewers would trip on them. The auto-generated scaffolding looked authored, not templated, making the contradictions easy to miss in review.

**Fix**: Replaced the four invented sections with `[NEEDS CLARIFICATION]` placeholder blocks that echo the user's `scopeBoundary` and `outOfScope`, so reviewers see the constraint the section needs to respect rather than templated contradictions. Future enhancement (deferred): add structured inputs (`dataRequirements`, `apiRoutes`, etc.) to `buildScopeContent` so `buildscope` can populate them when the user provides them during discovery — the placeholders are a stepping stone, not the final shape. Dead helpers (`pascalCase`, `primaryTable`, `eventTable`, `historyTable`, `componentBase`, `apiBasePath`, `resourceBase`, `entityRoot`, `featureWords`) were removed.

**Smoke-test**: rendered a scope with `featureDescription = "UAT foundation init database connections"` and `scopeBoundary = "No new tables — only take-over of 7 existing tables"`. Output now contains zero `companyuats` / `uatevents` / `uathistory` references and four `[NEEDS CLARIFICATION]` blocks that quote the boundary back. Confirmed with `npx tsx`.

## BUG-10 (medium) + PG-ignore rule — Embedded DB decryption noise on every consumer startup

**Where the bug lived**: this repo, [`mcp-server/src/config.ts`](../../../mcp-server/src/config.ts) (and compiled mirror [`mcp-server/dist/config.js`](../../../mcp-server/dist/config.js)).

**Cause**: `getDatabaseUrl()` checked the embedded credentials *first*, then fell back to env. The embedded credentials are kit-author state — populated at kit-generation time per `KitGenerationService` for the wxKanban-as-Consumer-#0 case. In a non-wxKanban consumer project, the embedded constant ships unpatched (empty strings), `validateEmbeddedCredentials()` returns false, and `console.error('Failed to decrypt embedded database URL: …')` fires on every startup before `WXKANBAN_MCP_DATABASE_URL` is consulted. Non-fatal but pollutes startup logs and obscures real errors.

**Fix**: Reordered priority so `WXKANBAN_MCP_DATABASE_URL` (env) is checked **first** — when present, the embedded path is never touched. Added `hasUsableEmbeddedCredentials()` to silently treat an unpatched placeholder as "not embedded," so even kit-author setups without env creds no longer log a spurious decrypt failure.

**Why this matters beyond the log noise**: this fix is the formal landing point for the **"consumer projects must recognize and ignore the wxKanban PG connection that ships in the kit"** rule. The kit-author DB credentials are useless (and a leakage concern) outside the wxKanban repo itself. Code now matches that intent: env-provided creds dominate, embedded creds are kit-author dogfooding only.

This rule should be added to spec 019 as a Resolved Decision in a future revision (decision #15: *consumer projects ignore embedded wxKanban PG creds; env-provided DB URL is the consumer source of truth*). Recorded here for now.

## Second-pass fixes (BUG-4, BUG-6 through BUG-9, BUG-11, BUG-12, BUG-13)

The remaining 8 issues from the report, all fixed in the same calendar day after the user opted to clear them in one go rather than schedule a follow-up sweep.

### BUG-4 (high) — `buildscope` writes scope files outside the project

**Where**: [`mcp-server/src/utils/project-kit.ts → resolveWorkspaceRoot`](../../../mcp-server/src/utils/project-kit.ts).

**Cause**: The resolver walked up from `process.cwd()` looking for an existing `specs/` directory and fell back to `process.cwd()` when none was found. The MCP server runs from `mcp-server/`, so a brand-new consumer install (no `specs/` yet) had files written into `mcp-server/specs/Project-Scope/…` instead of the project root.

**Fix**: Anchor on `.wxkanban-project.json` (the consumer-project root marker installed by the kit) first; that's canonical regardless of whether `specs/` exists. Legacy `specs/` walk-up kept as a fallback for kit-author dogfooding.

### BUG-6 (high) — CLI worker reports "created" regardless of server status

**Where**: [`wxkanban-agent/workers/ai/buildscope-worker.ts`](../../../wxkanban-agent/workers/ai/buildscope-worker.ts).

**Cause**: The worker hardcoded `Spec X created via project.buildscope` without checking `mcpResult.status`. When the server returned `status: 'draft_interview'` (no file written, needs more info), the CLI still printed success — users believed they had a spec when they didn't.

**Fix**: Branch on `mcpResult.status`. `draft_interview` now throws an error that surfaces `message`, `questions`, and `blockingIssues` from the response so the user knows exactly what to fill in. `updated` and `template_only` get distinct verbs in the success notes.

### BUG-7 (high) — CLI does not accept `--key=value`

**Where**: [`wxkanban-agent/apps/command-gateway/src/cli.ts`](../../../wxkanban-agent/apps/command-gateway/src/cli.ts).

**Cause**: The hand-rolled flag parser only supported `--key value` (space-separated). `--feature-description="x"` was parsed as a single boolean flag with key `feature-description="x"` — the MCP call then crashed with `featureDescription: Required`.

**Fix**: Pre-split on `=` before the existing parse loop so both conventions work. Standard shell habit (`--key=value`) now produces the same result as the space-separated form.

### BUG-8 (high) — Kebab/camel field-name contract is undocumented

**Where**: [`wxkanban-agent/apps/command-gateway/src/cli.ts → printAvailableCommands`](../../../wxkanban-agent/apps/command-gateway/src/cli.ts).

**Cause**: The worker accepts kebab-case flags and converts to camelCase server-side via `kebabToCamel()`, but the contract was undocumented. Trial-and-error to discover that `--feature-description` works and `--feature_description` does not, especially when combined with the BUG-7 quoting failure.

**Fix**: `--help` now documents the flag conventions explicitly: kebab-case is converted to camelCase, camelCase is passed through unchanged, both `--key value` and `--key=value` work, and includes worked examples.

### BUG-9 (medium) — Generic "500 Internal Server Error" hides MCP error body

**Where**: [`wxkanban-agent/workers/ai/buildscope-worker.ts`](../../../wxkanban-agent/workers/ai/buildscope-worker.ts).

**Cause**: On non-OK HTTP response, the worker threw `MCP /call returned ${status} ${statusText}` without reading the body — so structured `McpError` messages (e.g. `Validation error: featureDescription: Required`) only existed in the server log.

**Fix**: `await response.text()` on non-OK and append the first 500 chars to the thrown error. Wrapped in try/catch so a body-read failure doesn't mask the original error.

### BUG-11 (medium) — `start-http.mjs` requires running from `mcp-server/` cwd

**Where**: [`mcp-server/start-http.mjs`](../../../mcp-server/start-http.mjs).

**Cause**: The script used the relative path `dist/index-http.js` in the spawn args, so running it from anywhere other than `mcp-server/` produced `MODULE_NOT_FOUND`.

**Fix**: Resolve the dist path relative to `import.meta.url` and set `cwd: here` on the spawn so `node mcp-server/start-http.mjs` works from any directory.

### BUG-12 (low) — `isMeasurableMetric` placeholder check is overly aggressive

**Where**: [`mcp-server/src/utils/project-kit.ts → matchesPlaceholder`](../../../mcp-server/src/utils/project-kit.ts).

**Cause**: `matchesPlaceholder` used word-boundary matching for every marker in `PLACEHOLDER_MARKERS`, including `'placeholder'` — but "placeholder" is a real English word. Legitimate prose like "the URL still contains the placeholder string" was rejected as a TODO marker.

**Fix**: Special-case the `'placeholder'` marker so it matches only when bracketed (`[placeholder]`, `<placeholder>`), as a leading label (`placeholder:`), or as a whole-line value — not as a substring of natural prose. The unambiguous markers (`TODO`, `TBD`, `NEEDS CLARIFICATION`) keep their word-boundary matching.

**Smoke-test**: a metric like "the URL is still containing the placeholder string and we measure it under 5 seconds" now passes the placeholder check (only `NEEDS CLARIFICATION` from the BUG-5 generated stubs is reported, which is correct).

### BUG-13 (low) — `generateShortName` over-selects environment-name tokens

**Where**: [`mcp-server/src/utils/project-kit.ts → generateShortName`](../../../mcp-server/src/utils/project-kit.ts).

**Cause**: The stop-word list only excluded English articles and prepositions, so environment names (`uat`, `prod`, `dev`, `qa`, `stg`) leaked into the keyword set. A `featureDescription` of "UAT foundation init database connections" produced `001-foundation-init-database-connections-uat.md` and then the prior buildScope content invention (now fixed by BUG-5) prefixed every entity with `Uat`.

**Fix**: Added `uat`, `prod`, `dev`, `qa`, `stg`, `staging`, `production`, `development` to the stop-word list. `generateShortName('UAT foundation init database connections')` now returns `foundation-init-database-connections`.
