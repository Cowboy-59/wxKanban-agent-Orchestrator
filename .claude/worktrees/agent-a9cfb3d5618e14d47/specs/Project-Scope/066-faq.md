## Overview

SCOPE-066 adds a FAQ system to wxKanban that teaches users the product as they use it. FAQs are stored as `marketingassets` rows with `category='faq'` and `companyid=NULL` — one global product FAQ list, no new table. A row's `title` is the question, `content` is the answer, and `fileurl` is an optional answer video. A row with empty `content` is an **unanswered question**; `status` (`draft`/`published`) controls visibility.

Three capabilities sit on top of that storage:

1. **AI seed** — an admin-triggered action that infers as many sensible product/methodology FAQs as it can and returns them as `status='draft'` rows for review, reusing the SCOPE-065 `MarketingAIService`/`generateOnce` (Claude override), fail-open, human-reviewed pattern.
2. **SysAdmin management** — a new Marketing → FAQ tab to create/edit/answer FAQs and work an unanswered-questions queue. Built first.
3. **Read surfaces** — the User Dashboard, the Project Detail page, and a new VS Code Cockpit tab where authenticated users read published FAQs and can submit a question, which becomes an unanswered row for the admin to answer.

The trust model mirrors SCOPE-065: nothing the AI writes and no question a user submits is ever shown as a live FAQ until a SYSADMIN publishes it.

## Business Problem

wxKanban's mission is to teach customers a lifecycle methodology from zero to release — but the product surface area (six phases, scope-first, the kit, the Cockpit, billing, consulting) raises the same questions over and over. Today there is nowhere to capture those answers where users actually are: no FAQ exists, support questions repeat, and the methodology has to be re-explained one conversation at a time.

A curated FAQ closes three gaps at once. First, **repeat support load** — common questions get a durable, self-serve answer instead of a one-off reply. Second, **discoverability** — the answer shows up on the Dashboard, on Project Detail, and inside the VS Code Cockpit, i.e. exactly the three places a user is already working, rather than buried in external docs. Third, **the feedback loop** — when a user's question isn't already answered, they can ask it in place; it lands in an admin queue, gets answered once, and becomes a permanent FAQ that helps the next person.

The machinery to build this already exists: the `marketingassets` store (SCOPE-048) with the `category` column just added, the `MarketingAIService`/`generateOnce` AI plumbing (SCOPE-065), and the Cockpit tree (SCOPE-042). The gap is purely surfacing it as a FAQ category with a curation loop and read surfaces.

### Core Design

| Element | FAQ System |
| --- | --- |
| **Primary Actor** | A SYSADMIN curating the product FAQ — generating drafts, writing answers, and answering submitted questions |
| **Secondary Actors** | An authenticated **User** who reads FAQs and submits questions; the configured **LLM** (the AI-seed generator — never an autonomous publisher) |
| **Key Value** | Turn scattered, repeated product questions into a curated, always-available FAQ shown where users already work (Dashboard, Project Detail, Cockpit) — cutting repeat support and reinforcing the methodology, with nothing published without a human |
| **Storage** | `marketingassets`, `category='faq'`, `companyid=NULL` (global); `title`=question, `content`=answer, `fileurl`=optional video, `status`=draft/published; unanswered = empty `content` |
| **Boundary — IN** | the `faq` category on `marketingassets`; SysAdmin manage + unanswered queue; AI draft-seed; authenticated read on Dashboard/Project Detail/Cockpit; authenticated question submission (web); a read-only `faq.list` MCP tool for the Cockpit; Cockpit Videos grouped by category (Open/Training) |
| **Boundary — OUT** | public/marketing-site FAQ rendering; project-specific FAQs (global only); auto-publishing of AI output or submitted questions; asking from the Cockpit (read-only v1); FAQ search infrastructure; voting/helpfulness analytics; AI auto-answering of submitted questions |

## User Scenarios

### US1 — Admin seeds default FAQs with AI

A SYSADMIN opens the Marketing → FAQ tab and clicks "Generate default FAQs." The server calls the LLM (SCOPE-065 pattern), which returns a batch of product/methodology FAQs that appear as `draft` rows for review.

**Expected:** drafts are created (`category='faq'`, `status='draft'`, `companyid=NULL`); nothing is published automatically; the admin edits/approves each before it goes live.

### US2 — Admin writes / answers a FAQ

The SYSADMIN creates a FAQ (title + answer text + optional video URL) or opens an unanswered question and fills in the answer, then sets it `published`.

**Expected:** the row saves with `content` populated; once `published` it appears on the read surfaces; an answered question is no longer in the unanswered queue.

### US3 — User reads FAQs on the Dashboard

An authenticated user sees a FAQ panel on their dashboard listing published FAQs (question + answer, video if present).

**Expected:** only `published`, `category='faq'` rows show; drafts and unanswered questions never appear to users; locale-appropriate where variants exist.

### US4 — User asks a question from a read surface

From the Dashboard or Project Detail, a user submits a question.

**Expected:** a row is created with their question in `title`, empty `content`, marked unanswered; it lands in the admin's unanswered queue; the user gets a "thanks, we'll answer this" acknowledgement. It does not appear as a published FAQ until answered.

### US5 — Admin works the unanswered queue

The SYSADMIN sees all submitted, not-yet-answered questions in one list, answers one, and publishes it.

**Expected:** the queue = `category='faq' AND (content IS NULL OR content='')`; answering moves it out of the queue and (when published) onto the read surfaces.

### US6 — Cockpit shows FAQs in VS Code

A developer opens the FAQ section in the Cockpit tree; it lists published FAQs fetched via the read-only `faq.list` MCP tool.

**Expected:** published FAQs render read-only; selecting one shows its answer; consistent with how Help/Videos already work in the Cockpit.

### US7 — AI seed is unavailable or errors

The LLM key is missing, rate-limited, or returns garbage during seeding.

**Expected:** fail-open (SCOPE-065 pattern) — a clear "couldn't generate, try again" message, no partial/garbage rows saved, the FAQ surface stays fully usable, failure logged (Pino).

## Functional Requirements

### FR-001 — `faq` category

`'faq'` MUST be added to the asset category set (server zod enum + client constants) alongside `open|training`.

**Acceptance Criteria**:

- [ ] Server accepts/validates `category='faq'`; rejects unknown categories
- [ ] Client surfaces treat `faq` as a first-class category

### FR-002 — SysAdmin FAQ management

A new Marketing → **FAQ** tab MUST let a SYSADMIN list, create, edit, and delete FAQs (title=question, content=answer, optional video URL, locale, status), scoped to `category='faq'`, `companyid=NULL`.

**Acceptance Criteria**:

- [ ] Create/edit/delete persist correctly as `marketingassets` faq rows
- [ ] The tab lists faq rows separated into "Published/Draft FAQs" and "Unanswered questions"
- [ ] Endpoints require `authenticateToken` + `requireSysAdmin`; non-sysadmin → 403

### FR-003 — Unanswered-questions queue

The management surface MUST show all submitted, not-yet-answered questions, defined as `category='faq' AND (content IS NULL OR content='')`.

**Acceptance Criteria**:

- [ ] Queue lists exactly the empty-content faq rows
- [ ] Answering (filling `content`) + publishing removes a row from the queue
- [ ] A spam/irrelevant question can be deleted from the queue

### FR-004 — AI default-FAQ seed

The FAQ tab MUST offer an admin-only "Generate default FAQs" action that infers product/methodology FAQs via the shared marketing-AI service (`generateOnce`, Claude override), returning them as `status='draft'` rows for review. It MUST be fail-open and soft-throttled.

**Acceptance Criteria**:

- [ ] One action creates multiple `draft` faq rows; nothing is auto-published
- [ ] Model failure/missing key/garbage → handled "couldn't generate" message, no partial rows saved, logged (Pino); surface stays usable
- [ ] Endpoint is SYSADMIN-gated and soft-throttled against runaway spend

### FR-005 — Publish / visibility model

Only `status='published'` faq rows with non-empty `content` MUST be visible to non-admin users; drafts and unanswered rows MUST never appear on read surfaces.

**Acceptance Criteria**:

- [ ] Read endpoints return only published, answered faq rows
- [ ] A draft or unanswered row is never returned to a non-admin caller

### FR-006 — Dashboard FAQ read

The User Dashboard MUST show a FAQ panel listing published FAQs (question, answer, video if present), read-only.

**Acceptance Criteria**:

- [ ] Panel lists published global FAQs; renders optional video
- [ ] No draft/unanswered content leaks

### FR-007 — Project Detail FAQ read

The Project Detail page MUST show the same global published FAQ list (read-only).

**Acceptance Criteria**:

- [ ] Project Detail displays published global FAQs (no project-specific filtering this scope)

### FR-008 — Authenticated question submission

From the Dashboard and Project Detail, an authenticated user MUST be able to submit a question, creating an unanswered faq row (`title`=question, empty `content`).

**Acceptance Criteria**:

- [ ] Submitting creates exactly one empty-content faq row and shows an acknowledgement
- [ ] The submitted question appears in the admin unanswered queue, never as a published FAQ
- [ ] Endpoint requires authentication (any logged-in user); basic abuse guard (length limits / soft throttle)

### FR-009 — Cockpit FAQ tab (read-only v1)

The VS Code Cockpit MUST show a FAQ section listing published FAQs via a new **read-only** `faq.list` MCP tool, registered in the MCP `PERMISSION_MATRIX`. Asking from the Cockpit is out of scope for v1.

**Acceptance Criteria**:

- [ ] `faq.list` returns published FAQs and is registered in `PERMISSION_MATRIX` (no "Unknown tool")
- [ ] The Cockpit renders them read-only, consistent with Help/Videos
- [ ] The tool can reach the FAQ data (see Technical Sections — data-path dependency)

### FR-010 — Optional answer video

A FAQ answer MAY include a video, stored in `fileurl`; read surfaces MUST render it when present and omit it cleanly when absent.

**Acceptance Criteria**:

- [ ] A FAQ with a video shows it; one without shows none (no broken element)

### FR-011 — Cockpit videos grouped by category

The Cockpit Videos section MUST keep its existing docs how-to videos (the public docs index) **and** add two new subtrees — **Open** and **Training** — listing `marketingassets` video rows (`type='video'`) grouped by `category`.

**Acceptance Criteria**:

- [ ] The existing docs how-to videos still appear
- [ ] `marketingassets` videos render under an "Open" subtree and a "Training" subtree by their `category`
- [ ] `faq`-category videos are excluded from these subtrees (those are FAQ answers, not catalog videos)
- [ ] A category with no videos shows no empty subtree (or an explicit empty state)

## Technical Sections

### Data model (no new table)

FAQs are `marketingassets` rows: `category='faq'`, `companyid=NULL` (global), `title`=question, `content`=answer, `fileurl`=optional video, `locale`, `status` (`draft`→`published`). Unanswered = `content IS NULL OR content=''`. Reuses the `idx_marketingassets_category` index already added; a partial index on unanswered faqs is a possible perf follow-up, not required at this scale.

### Category enum

Add `'faq'` to the server zod enum in `marketingAdmin.ts` and the client `CATEGORIES` constant — extends the `open|training` work already shipped. One-line additions; no migration (column is already `varchar(50)`).

### AI seed service

Extend the existing `MarketingAIService` (SCOPE-065) with a `generateFaqDefaults()` method: a focused system prompt grounded in wxKanban product/methodology knowledge, strict JSON output (array of `{question, answer}`), JSON-parsed with fence-stripping, fail-open to a handled error, Pino-logged, never throws. Runs through `generateOnce` with the marketing Claude override (`MARKETING_LLM_PROVIDER`). Soft-throttled like SCOPE-065's actions. No new AI infra.

### Routes — two routers, two trust levels

- **Admin** (reuse `marketingAdmin.ts`, `authenticateToken` + `requireSysAdmin`): FAQ management rides the existing `/assets` CRUD with `category=faq`; add the unanswered-queue read and a FAQ-seed (AI) endpoint. SYSADMIN-gated.
- **User** (new `src/server/routes/faq.ts`, mounted via `index.ts → app.ts`, `authenticateToken` only — any logged-in user): `GET /api/faq` (published global FAQs, for Dashboard + Project Detail) and `POST /api/faq/questions` (submit a question → empty-content faq row). These exist because the read/ask surfaces are not sysadmin — the existing marketing routes can't serve them.

### Cockpit MCP — the tracked dependency (FR-009 / FR-011)

A new read-only MCP tool (`faq.list`, and the categorized-video fetch for FR-011) registered in `PERMISSION_MATRIX` (or it's rejected pre-dispatch as "Unknown tool"), plus FAQ + categorized-video sections in `CockpitTreeProvider`, plus a hosted MCP redeploy.

**Open risk to resolve at `createSpecs`:** the hosted MCP's DB may not be the app DB where `marketingassets` lives. Resolution options to decide then: (a) point/extend the hosted MCP to read the app DB for these tools, or (b) have the tool(s) proxy the new `GET /api/faq` (and an equivalent categorized-videos) app endpoint. This MUST be settled before the Cockpit task is built; it does **not** block the SysAdmin/web work (built first). One decision covers both FAQs and categorized videos — likely one MCP tool/endpoint returning categorized assets.

### Client

- **SysAdmin:** new `FAQ` entry in `MarketingTabs`, new page `src/client/pages/SysAdmin/marketing/Faq.tsx` — Published/Draft list + Unanswered queue + create/edit/answer editor (title + answer textarea + optional video URL) + "Generate default FAQs" button. Reuses the existing `fetch(credentials:'include')` + `useState` pattern.
- **User read:** a FAQ panel component reused on the User Dashboard and Project Detail page, calling `GET /api/faq`; plus a small "Ask a question" form posting to `POST /api/faq/questions`.
- **Cockpit:** a FAQ tree section calling `faq.list`, read-only, mirroring Help/Videos; plus the Open/Training video subtrees (FR-011).

### Environment / infra

Reuses SCOPE-065 env (`MARKETING_LLM_PROVIDER`/`MARKETING_LLM_MODEL`/`ANTHROPIC_API_KEY`). No new tables, no IAM, no background jobs. The only new infra is the hosted MCP redeploy for the read tool(s) serving FAQs + categorized videos.

### Conventions

Routes via `index.ts → app.ts`; DB via `src/db/client.ts`; 100% TypeScript (no `any`/`@ts-ignore`); Pino-only; fences written by the orchestrator at `implement`; nothing pushed until the user says push.

## Success Criteria

1. **The FAQ category is live end to end.** `marketingassets` accepts `category='faq'` (server + client), and faq rows drive every surface. *(FR-001)*
2. **A SYSADMIN can curate FAQs from one place.** The Marketing → FAQ tab lists, creates, edits, deletes, and answers FAQs, with Published/Draft and Unanswered sections clearly separated. *(FR-002, FR-003)*
3. **AI seeds drafts, never publishes.** "Generate default FAQs" produces multiple `draft` faq rows from product knowledge; a forced model failure returns a handled error, saves nothing, logs it, and leaves the tab usable. *(FR-004)*
4. **Users never see unfinished content.** Only published, answered, global faq rows reach non-admin read surfaces; no draft or unanswered row ever leaks. *(FR-005)*
5. **FAQs appear where users already are.** Published FAQs render read-only on the User Dashboard, Project Detail, and the Cockpit FAQ tab (via `faq.list`). *(FR-006, FR-007, FR-009)*
6. **The ask-loop closes.** An authenticated user submits a question → it lands in the admin unanswered queue → the admin answers and publishes → it shows on the read surfaces; round-trip works without leaking the question as a live FAQ before it's answered. *(FR-008, FR-003, FR-005)*
7. **Cockpit videos are grouped by category, both sources intact.** The Cockpit Videos section shows the existing docs how-to videos plus an Open and a Training subtree of `marketingassets` videos. *(FR-011)*
8. **No new infrastructure beyond one MCP redeploy.** Ships on `marketingassets` + the existing `generateOnce`/`MarketingAIService` plumbing — no new tables, IAM, or background jobs; the only new infra is the hosted MCP redeploy for the read tool(s). *(Technical Sections)*

## Constraints & Notes

### Constraints

- **Reuse, don't reinvent.** No new table — FAQs are `marketingassets` rows (`category='faq'`, `companyid=NULL`). AI seed reuses `MarketingAIService`/`generateOnce` + the SCOPE-065 Claude override and fail-open pattern. No new AI infra, no background jobs.
- **Human-in-the-loop.** AI output and submitted questions are always drafts/unanswered until a SYSADMIN publishes. Nothing auto-publishes.
- **Trust gate is single-sourced.** All read surfaces go through one visibility rule (published + non-empty `content`); no surface re-implements it.
- **Build order: SysAdmin first.** Admin manage + unanswered queue + AI seed ship first; then web read/ask (Dashboard, Project Detail); the Cockpit tab + categorized-video subtrees last (gated on the data-path decision).
- **Correct plumbing.** Routes via `index.ts → app.ts`; DB via `src/db/client.ts`; 100% TypeScript; Pino-only; fences by the orchestrator at `implement`; nothing pushed until the user says push.
- **Orchestrator-first.** Implement via `createSpecs` → `implement`.

### Out of Scope (own later scopes)

- Public / marketing-site FAQ rendering (authenticated surfaces only this scope).
- Project-specific FAQs (global only — would need a project link on the row).
- Asking from the Cockpit (read-only in v1; web surfaces handle submission).
- FAQ search infrastructure, voting/helpfulness analytics, and AI auto-answering of submitted questions.

### Dependencies

- **SCOPE-048** (`marketingassets`) + the `category` column/index already added (the `open|training` work); this scope adds `'faq'` to the enum.
- **SCOPE-065** (`MarketingAIService`, `generateOnce`, `MARKETING_LLM_PROVIDER`/`ANTHROPIC_API_KEY`) for the AI seed.
- **SCOPE-042** Cockpit (`CockpitTreeProvider`, Videos/Help sections) + the hosted MCP (`PERMISSION_MATRIX`, redeploy) for FR-009/FR-011.
- **The Cockpit data-path / DB-reachability decision** (Technical Sections) — the one unresolved item; MUST be settled at `createSpecs` before the Cockpit task. Does not block SysAdmin/web work.
- The project i18n locale set (SCOPE-051/053) if FAQ localization is exercised (`locale` field already exists).
